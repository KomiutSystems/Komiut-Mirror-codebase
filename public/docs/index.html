Introduction

REST API for the Komiut / 2Safiri matatu SACCO platform: authentication, vehicles, routes, queues, bookings, transactions, saccos, users and loyalty points.

Base URL: http://localhost 
This documentation covers the Komiut / 2Safiri Matatu API.

<aside>All endpoints require the <code>X-App-Key</code> brand header, and authenticated endpoints require a Sanctum bearer token.
As you scroll, you'll see code examples for working with the API in different programming languages in the dark area to the right (or as part of the content on mobile).
You can switch the language used with the tabs at the top right (or from the nav menu at the top left on mobile).</aside>

Authenticating requests

To authenticate requests, include an Authorization header with the value "Bearer {YOUR_SANCTUM_TOKEN}".

All authenticated endpoints are marked with a requires authentication badge in the documentation below.

Obtain a bearer token from the POST api/login or POST api/register endpoints. All requests must also send the X-App-Key brand header.

Billing administration

Create or update a billing plan

requires authentication

Pass id to update an existing plan, omit it to create one. Invoice for a period = base_fee + per_vehicle_fee × active vehicles (capped at vehicle_cap).

Example request:
curl --request POST \
    "http://localhost/api/v1/auth/billing/plans/save" \
    --header "Authorization: Bearer {YOUR_SANCTUM_TOKEN}" \
    --header "Content-Type: application/json" \
    --header "Accept: application/json" \
    --data "{
    \"id\": 1,
    \"name\": \"Standard\",
    \"description\": \"Up to 50 vehicles\",
    \"billing_cycle\": \"monthly\",
    \"base_fee\": 500,
    \"per_vehicle_fee\": 100,
    \"vehicle_cap\": 50,
    \"currency\": \"KES\",
    \"is_active\": true
}"

Get the fare for a trip

requires authentication

Returns the SACCO-set price for a route between two stops. This value is authoritative: it is exactly what the booking and the STK push will charge, so the app should display it and never compute its own. Served from cache, so it is cheap to call on every price preview.

Example request:
curl --request GET \
    --get "http://localhost/api/v1/auth/book_a_ride/fare?sacco_id=1&route_id=5&from_id=12&to_id=18" \

Driver — queue & trip lifecycle

The driver-facing counterpart to the dispatcher's queues/add. Everything the dispatcher form supplies from the client — the vehicle, the fare, the queue status — is here derived server-side from the authenticated driver's active assignment, so a driver can only ever queue THEIR vehicle at the SACCO's own price. Mirrors the C# Queue/join, Queue/exit and Trips/start-trip flow.

Join a queue

requires authentication

The driver queues the vehicle they are assigned to today at a terminus for a route. The vehicle comes from the driver's active assignment (never the body), the fare from the SACCO's route pricing, and the status is Pending — the client sends only where it is going.
